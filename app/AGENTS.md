# Codonaut — инструкции по разработке

## Описание проекта

Codonaut — мобильное Android-приложение для персонализированного обучения подростков основам программирования и алгоритмического мышления.

Приложение разрабатывается в рамках курсовой работы студента специальности 09.02.07 «Информационные системы и программирование».

Основные направления обучения: Python, JavaScript и Java.

Цель проекта — создать законченное мобильное приложение с интерактивными уроками, заданиями, игровыми механиками, сохранением прогресса и адаптивным подбором сложности на основе формализованных правил.

Полноценный генеративный ИИ-помощник и облачная синхронизация учебного прогресса не входят в текущий объём разработки.

## Архитектура

Проект использует разделение ответственности между пакетами:

- `core` — общие компоненты, тема и инфраструктурные элементы.
- `data` — реализация репозиториев, локальное и удалённое хранение данных.
- `domain` — модели, интерфейсы репозиториев и бизнес-логика.
- `features` — пользовательские экраны, ViewModel и UI-состояния.
- `di` — контейнер зависимостей.

Перед внесением изменений изучай актуальную структуру файлов. Фактический исходный код является приоритетным источником информации о реализации.

Не размещай бизнес-логику в Activity или Composable-функциях.

Сохраняй однонаправленный поток данных: UI передаёт события во ViewModel, ViewModel обновляет состояние, UI отображает состояние.

Используй существующие репозитории, модели и компоненты вместо создания дублирующих реализаций.

## Хранение данных

Firebase Authentication предназначен исключительно для управления учётными записями и аутентификации.

Локальные пользовательские данные хранятся через Room.

Preferences DataStore используется для небольших параметров приложения, идентификаторов активного и гостевого профилей и состояния онбординга.

Гостевой режим должен оставаться доступным без подключения к интернету.

При регистрации гостя его локальный profileId должен сохраняться, чтобы не потерять связанные учебные данные.

Не сохраняй пароли в локальной базе данных или DataStore. Не добавляй серверные ключи и секреты в Git.
